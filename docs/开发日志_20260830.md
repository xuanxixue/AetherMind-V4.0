## 一、V5 EqProp MNIST 训练问题分析

### 1.1 背景
用户运行了两组3层EqProp (784→500→500→10) MNIST训练：
- 第一组：T_free=40, T_clamp=20, 同步松弛，50 epochs → best test_acc=29.72%
- 第二组：T_free=60, T_clamp=30, async(Gauss-Seidel)松弛，跑到epoch 12中断

### 1.2 问题诊断
- **前11个epoch完全不学习**：train_acc卡在0.1126（随机水平），loss在1.88附近不动
- **epoch 16-32才开始下降**：loss从1.88降到1.75，acc升到30%
- **epoch 33后崩塌**：loss反弹回1.88，acc跌回0.10，说明梯度爆炸/不稳定
- **tanh激活+3层架构**在当前超参下不稳定

### 1.3 用户决策
- 先回退到2层EqProp，不继续M4/M5
- 核心问题：梯度裁剪防止epoch 6-11爆炸、换激活函数、加第三层表达能力

### 1.4 相关文件
- `D:\AetherMind-Nano3\V5\train_mnist.py` — EqProp MNIST训练脚本

### 2.2 阶段定义
| 阶段 | 内容 | 机制 |
|------|------|------|

| F | KG对齐 | 冻结主干，训练Entity→Atom映射 |
| G | 纯净对话SFT | 解冻6层，lr=2e-5，清洗数据 |

### 2.3 7天步数分配
| 阶段 | 步数 | 预计耗时 |
|------|------|---------|
| A+B+C | 20K+40K+80K=140K | ~56h |
| D | 5K | ~1h |
| E | 3K | ~1h |
| F | 2K | ~0.5h |
| G | 100K | ~93h |
| **合计** | **250K** | **~6.5天** |

## 三、三层验证钩子系统

### 3.1 设计原则
用户提供了完整的三层验证结构设计，核心思想：**训练脚本验证的不是"模型好不好"，而是"当前权重将来能不能无损迁移到推理架构"**。

### 3.2 三层结构
| 层 | 频率 | 内容 | 作用 |
|----|------|------|------|
| 第1层 | 每500步 | τ稳态斜率、过饱和预警、NaN/Inf扫描、梯度健康max/min比 | 数值卫生，fail-fast |
| 第2层 | 每5000步 | 压缩KL（平移不变性）+ 推理烟测 | 迁移性监控（双架构核心） |
| 第3层 | 阶段末 | 转换→预热→复杂度→needle→质量，输出JSON报告 | 正式验收+scaling数据 |

### 3.3 "谁主导"物理占比分析
注意力能量三项：
```
E_eff = QK^T/√dh (DL内容项) - βT·logτ (信息素项) - T·C (固化项)
```
物理项能量占比 = Var(βT·logτ + T·C) / Var(E_eff总)
- <5% → DL主导，物理层是装饰
- >30% → 物理项实质性塑造注意力路由

### 3.4 实现文件
- **新建** `D:\AetherMind-Nano3\src\validation\__init__.py`
- **新建** `D:\AetherMind-Nano3\src\validation\hooks.py` — ValidationHooks类，含：
  - `layer1_numeric_check()` — τ稳态/饱和/NaN/梯度
  - `energy_ratio_analysis()` — 物理能量占比+主导权判定
  - `migration_check()` — 压缩KL（平移不变性）
  - `inference_smoke_test()` — 推理烟测
  - `phase_end_report()` — 阶段末JSON报告
  - `on_step()` — 统一调度入口
  - 所有指标写入 `validation_logs/validation_metrics.jsonl`

### 3.5 注意力能量分量追踪
- **修改** `D:\AetherMind-Nano3\src\model\attention\pheromone_thermo.py`
- forward中新增 `_last_E_components = {E_qk, E_tau, E_cons, E_eff}`
- 供验证钩子实时计算物理占比

### 3.6 训练循环集成

## 四、GPU显存守护系统

### 4.1 需求
用户要求：检测到显存OOM风险时直接清理，防止训练中断，任何东西都不能阻止模型训练。

### 4.2 实现
- **修改** `D:\AetherMind-Nano3\src\utils\gpu_guard.py`
- 新增 `GPUMemoryWatchdog` 类（后台守护线程）：
  - 每10秒轮询nvidia-smi查显存
  - **>85%**：`gc.collect() + torch.cuda.empty_cache() + synchronize()`（限流5秒）
  - **>95%**：紧急释放，杀掉非白名单GPU进程
  - 统计常规清理次数/紧急释放次数
- train_v4.py的setup()中自动启动watchdog
- 白名单保护：系统进程、explorer、cmd、python.exe本身、IDE等

### 4.3 已有功能
- `pre_train_gpu_cleanup()` — 训练前清理非必要GPU进程
- `emergency_free_gpu_memory()` — 紧急释放显存
- `get_gpu_memory()` / `get_gpu_processes()` — 查询工具

### 5.4 第三版：纯Win32 API (monitor_gui.py 重写)
- 零依赖，仅用ctypes调用user32/gdi32/kernel32
- 原生窗口，GDI手绘5条实时曲线
- 4组指标面板：训练状态/物理演化/验证监控/GPU显存
- 训练日志实时显示（EDIT控件）
- 独立GPU监控线程（每2秒nvidia-smi）

### 5.5 闪退Bug（关键）
**根因**：ctypes函数原型未声明 `restype`，64位Windows上GDI句柄（64位指针）被默认截断为32位 `c_int`，传入无效句柄后GDI崩溃。

**具体问题**：
- `CreateFontIndirectW` / `CreatePen` / `CreateSolidBrush` / `SelectObject` / `BeginPaint` / `CreateWindowExW` 等返回句柄的函数全部缺 `restype=c_void_p`
- `LOGFONTW` 用 `create_string_buffer(280)` + 硬偏移memmove，结构不规范
- `wnd_proc` 无异常保护，WM_PAINT中任何异常直接崩溃
- 窗口闪退时训练子进程已启动但未被回收 → "停止不了"

**修复方案**（待系统恢复后写入）：
1. 全部Win32/GDI函数显式声明 `argtypes` + `restype=c_void_p`
2. `LOGFONTW`/`WNDCLASSEXW`/`PAINTSTRUCT`/`MSG` 用正式ctypes.Structure定义
3. `wnd_proc` 外层try/except，异常写日志不闪退
4. `WM_DESTROY` 强制 terminate→wait(5s)→kill 训练进程
5. 新增终端能力：底部输入框（回车发命令到stdin）+ 停止/启动按钮
6. `stop_event.set()` 通知所有后台线程退出

## 八、关键决策记录

1. **V5先回2层**：3层EqProp在当前超参下不稳定，前11epoch不学习，33epoch后崩塌，先稳定2层再扩展
2. **Phase G lr=2e-5**：3e-5对6层全解冻偏高，导致loss震荡7.6~9.2，降为2e-5
3. **纯Win32 API而非PySide6**：环境缺Qt插件，PySide6无法运行；ctypes零依赖且轻量
4. **exe而非.cmd**：用户要求独立软件，不依赖系统cmd终端；PyInstaller --onefile --windowed
5. **训练进程内显存守护**：OOM预防必须在训练进程内部做（empty_cache），外部监控只能告警
6. **验证钩子独立模块**：`src/validation/hooks.py` 不污染训练主循环，未来2.6T训练可复用
